# Panda Live 深色模式主色改蓝方案

| 项目 | 内容 |
|---|---|
| 版本 | 0.1（评审稿） |
| 日期 | 2026-11-25 |
| 范围 | **仅深色主题主色**，浅色主题完全不动 |
| 基线 | 真实构建产物 `dist/`，非手绘原型 |
| 覆盖样式 | `doc/ui-dark-blue.css`（叠加在应用样式之后即可预览） |

---

## 1. 为什么要换

当前深色主题主色是亮绿 `#41bf95`。在真实深色界面里存在三个问题：

1. **荧光感**：高饱和亮绿压在 `#1e1e1e` 上视觉冲击强，久看疲劳。
2. **语义混淆**：绿色在深色工具里普遍代表"成功 / 通过 / 新增"，用作全局主色会与状态色语义冲突。
3. **不符合主流**：VS Code 蓝、GitHub Dark 蓝、Linear 蓝紫——专业深色工作台几乎不用绿作主色。

> 浅色主题的深绿 `#0b6b4f` 观感正常，**保持不变**。

---

## 2. 换色方案

GitHub Dark 风格蓝色，与编辑器选区色 `rgba(38,79,120,.9)` 同族，天然协调：

| token | 现状（深绿系） | 改为（蓝色系） | 用途 |
|---|---|---|---|
| `--accent` | `#41bf95` | **`#58a6ff`** | 活动标签/按钮、链接、图标、选中节点、焦点元素 |
| `--accent-strong` | `#67d6b0` | **`#79b8ff`** | hover / 强强调 |
| `--accent-soft` | `#133a2f` | **`#12283f`** | 选中行、标签背景、引用块底色 |
| `--accent-fg` | `#07261d` | **`#061525`** | 主色填充按钮上的文字 |
| `--focus-ring` | `rgba(65,191,149,.55)` | **`rgba(88,166,255,.55)`** | 键盘焦点环（本方案新增 token） |

**无需改动**：编辑器选区 `--editor-selection` 本就是蓝色，与新主色一致；语法高亮 `--cm-*`、状态色 `--danger/--warning/--info` 都不依赖主色，保持原样。

**关键实现优势**：深色主题所有主色使用都通过 `--accent*` 变量（已逐行核对 base.css），因此只需覆盖 5 个 token，零结构改动、零选择器改动。

---

## 3. 对比度核验

从真实渲染截图的观察：

| 场景 | 表现 |
|---|---|
| 文件树选中节点 | 亮蓝字 + 深蓝底，清晰 |
| Git 徽标 | 亮蓝底 + 深蓝字，对比充足 |
| 活动模式按钮 | 亮蓝填充 + 深蓝图标，清晰 |
| 链接 / 引用块左边框 | 亮蓝，醒目但不刺眼 |
| 状态栏分支名 | 亮蓝，小面积可读 |
| 焦点环 | 亮蓝半透明，深底上明显 |

## 5. 实施清单

评审通过后，把 `doc/ui-dark-blue.css` 的值合入 `src/styles/base.css`：

1. `:root[data-theme="dark"]` 段替换 4 个 `--accent*` 值。
2. `--focus-ring` 深色值改为蓝色（与 `ui-font-controls.css` 合并时以本节为准）。
3. 跑 `npm run verify`（lint + test + build）。
4. 用真实深色截图复核：主色元素全部变蓝、无残留绿色、对比度达标。

**独立回滚**：本方案与字体控件方案（`ui-font-controls.css`）互相独立，可分别采纳或回滚。
